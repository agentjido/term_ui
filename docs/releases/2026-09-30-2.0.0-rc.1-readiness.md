# TermUI 2.0.0-rc.1 readiness

This record covers RC1 preparation. The version in `mix.exs` and the changelog
is `2.0.0-rc.1`. The maintainer requested completion of the
[RC1 work plan](../plans/2026-09-30-001-refactor-rc1-documentation-plan.md)
before shipment. Hex publication and release tags remain separate maintainer
actions. No package was uploaded by this preparation work.

## Package evidence

`mix hex.build` produced a local package with 150 files. Its SHA256 is:

```text
d25a3c7e11969fee809f0af0614a47af12d36a4ba5788b96cb3053fbb381f585
```

The package contains the public guides, source NIF inputs, browser JavaScript
and CSS, and `Mix.Tasks.Termui.Run`. It excludes maintainer `docs`, examples,
tests, repository configuration, notes, and compiled native libraries.

Two fresh directories were created from the tar contents. Each production
consumer used the extracted package as a path dependency and the repository
lockfile to fix the validation dependency versions. This validates the
package contents; it is not a claim that Hex can already fetch RC1.

Both consumers compiled with warnings as errors and ran all four recipes
through their public API. They checked a drawn result, normal runtime and
backend-owner exit, version, browser assets, and the consumer Mix task.
The source consumer built and loaded the TTY NIF. The disabled consumer had
no compiled TTY NIF and used the deterministic backend.

## Terminal and host evidence

The existing platform CI runs real Unix PTY and Windows ConPTY checks with
source and disabled NIF policies. Windows checks use Command Prompt and Git
Bash inside ConPTY. Browser and Ghostty checks remain part of the required
CI gate. The Windows job is not a physical Windows Terminal or Mintty result.

The maintainer reported a passing v2 macOS showcase Raw check with identical
saved `stty` settings before and after exit. The exact commit, terminal app
version, and profile were not supplied. This is earlier v2 physical evidence,
not a new physical run of the RC1 boundary fixes. Those fixes do not change
terminal acquisition or cleanup. Issue #35 is closed.

Physical Windows Terminal and Mintty profiles remain unverified. The maintainer
has no Windows machine and approved proceeding with the committed fixes.
Those checks are deferred follow-up work and do not block RC1. Keep
[#5](https://github.com/agentjido/term_ui/issues/5) and
[#6](https://github.com/agentjido/term_ui/issues/6) open for those results.
The [terminal guide](../../guides/terminal-checks.md) gives the correct v1/v2
probe paths and the fields needed for a later report.

## Maintainer decision and remaining scope

Complete the work plan before shipping RC1, retain required CI, and preserve
v1 separately. The four existing consumer projects remain the example layout.
There is no separate unfinished RC1 example or property-test phase after this
record passes its checks. Optional future tools/features remain in the deferred
guide and historical proposal; they are not RC1 completion conditions.

Shipment still requires the maintainer's separate Hex/tag action. Physical
Windows frontend results remain tracked follow-up issues. Neither absence is
represented as a failed source check or as a physical pass.
